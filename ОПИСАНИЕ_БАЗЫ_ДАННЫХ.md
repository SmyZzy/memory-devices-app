# Описание структуры базы данных
## Система «Запоминающие устройства ЭВМ»

База данных MySQL развернута в облаке Aiven (хост: memory-db-memory-devices-app.h.aivencloud.com, порт: 19732, имя БД: defaultdb). Используется кодировка UTF8MB4 для корректного хранения русского языка.

---

## 1) Таблица «groups» — справочник учебных групп

**Назначение:** Хранит список учебных групп студентов. Используется для классификации студентов и фильтрации результатов тестирования.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор группы, первичный ключ (PRIMARY KEY) |
| `name` | VARCHAR(50), UNIQUE | Название учебной группы (например: «ИС-101», «ИС-102», «ИС-201») |

**Особенности:**
- Название группы должно быть уникальным (ограничение UNIQUE)
- Группы создаются автоматически при инициализации БД (init.js) или вручную через SQL
- По умолчанию создаются группы: ИС-101, ИС-102, ИС-201, ИС-202, ИС-301

**Связи:**
- С таблицей `users` через внешний ключ `users.group_id` → `groups.id` (при удалении группы поле group_id становится NULL)

## 2) Таблица «users» — учётные записи пользователей

**Назначение:** Содержит информацию о всех пользователях системы (студенты и преподаватели). Хранит данные для авторизации и идентификации пользователей.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор пользователя, первичный ключ (PRIMARY KEY) |
| `username` | VARCHAR(100), UNIQUE | Логин пользователя для входа в систему (например: «admin», «ivanov1») |
| `password` | VARCHAR(255) | Хешированный пароль (используется алгоритм BCrypt с salt rounds = 10) |
| `role` | ENUM('student', 'teacher') | Роль пользователя в системе (студент или преподаватель) |
| `first_name` | VARCHAR(100) | Имя пользователя |
| `last_name` | VARCHAR(100) | Фамилия пользователя |
| `middle_name` | VARCHAR(100) | Отчество пользователя |
| `group_id` | INT, NULL | Идентификатор учебной группы (только для студентов), внешний ключ → groups.id |
| `created_at` | DATETIME, DEFAULT CURRENT_TIMESTAMP | Дата и время создания аккаунта |

**Особенности:**
- Пароли хранятся в зашифрованном виде (BCrypt hash), исходный пароль восстановить невозможно
- Поле `group_id` может быть NULL (для преподавателей и нераспределённых студентов)
- При удалении группы поле `group_id` становится NULL (ON DELETE SET NULL)
- Логин (`username`) должен быть уникальным

**Связи:**
- С таблицей `groups` через внешний ключ `users.group_id` → `groups.id`
- С таблицей `test_results` через внешний ключ `test_results.user_id` → `users.id` (при удалении пользователя удаляются и его результаты тестирования — ON DELETE CASCADE)

**Учётные записи по умолчанию:**
- Преподаватель: `admin` / `teacher123`
- Студенты: `ivanov1`, `petrov1`, `sidorov1` и др. / `student123`

## 3) Таблица «theory_topics» — темы теоретического материала

**Назначение:** Содержит список тем курса «Запоминающие устройства ЭВМ» с теоретическим материалом и ссылками на файлы лекций.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор темы, первичный ключ (PRIMARY KEY) |
| `title` | VARCHAR(255), NOT NULL | Название темы (например: «Тема 1. Оперативная память») |
| `short_content` | TEXT, NOT NULL | Краткое содержание темы в формате HTML (отображается на странице темы) |
| `file_path` | VARCHAR(255), NULL | Путь к файлу лекции (например: «files/theme1_memory.docx») |
| `order_num` | INT, DEFAULT 0 | Порядок отображения тем (сортировка: по возрастанию) |

**Особенности:**
- Версия 1.0 системы содержит 4 темы:
  1. Тема 1. Оперативная память (file_path: files/theme1_memory.docx)
  2. Тема 2. Кеш-память (file_path: files/theme2_cache.ppt)
  3. Тема 3. Накопители (file_path: files/theme3_hdd.ppt)
  4. Тема 4. Системы RAID (file_path: files/theme4_raid.doc)
- Поле `short_content` содержит HTML-разметку (заголовки h3/h4, списки ul/li, параграфы p)
- Поле `file_path` может быть NULL, если файл лекции не прикреплён
- Темы выводятся на странице /theory.html в порядке `order_num`

**Связи:**
- С таблицей `mini_tests` через внешний ключ `mini_tests.topic_id` → `theory_topics.id` (при удалении темы удаляются и связанные мини-тесты — ON DELETE CASCADE)
- С таблицей `full_tests` через внешний ключ `full_tests.topic_id` → `theory_topics.id` (при удалении темы поле topic_id становится NULL — ON DELETE SET NULL)
- С таблицей `test_results` через внешний ключ `test_results.topic_id` → `theory_topics.id` (при удалении темы поле topic_id становится NULL — ON DELETE SET NULL)

## 4) Таблица «mini_tests» — вопросы мини-тестов

**Назначение:** Содержит вопросы для мини-тестов, которые студенты проходят после изучения каждой темы. Каждая тема имеет по 4 вопроса.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор вопроса, первичный ключ (PRIMARY KEY) |
| `topic_id` | INT, NOT NULL | Идентификатор темы, к которой относится вопрос, внешний ключ → theory_topics.id |
| `question` | TEXT, NOT NULL | Текст вопроса |
| `option_a` | TEXT, NOT NULL | Вариант ответа A |
| `option_b` | TEXT, NOT NULL | Вариант ответа B |
| `option_c` | TEXT, NOT NULL | Вариант ответа C |
| `option_d` | TEXT, NOT NULL | Вариант ответа D |
| `correct_answer` | ENUM('A', 'B', 'C', 'D'), NOT NULL | Правильный вариант ответа |

**Особенности:**
- Каждая тема (topic_id) имеет 4 вопроса (всего 16 вопросов на 4 темы)
- Вопросы отображаются на странице theory-detail.html после изучения теории
- Варианты ответов A, B, C, D отображаются как радиокнопки
- Правильный ответ хранится одной буквой (A, B, C или D)
- При удалении темы все связанные вопросы удаляются автоматически (ON DELETE CASCADE)

**Связи:**
- С таблицей `theory_topics` через внешний ключ `mini_tests.topic_id` → `theory_topics.id`

**Пример записи:**
| id | topic_id | question | option_a | option_b | option_c | option_d | correct_answer |
|----|----------|-----------|----------|----------|----------|----------|---------------|
| 1 | 1 | Что такое ЗУ? | Устройство вывода | Устройство хранения | Устройство обработки | Устройство передачи | B |

## 5) Таблица «full_tests» — вопросы полного теста

**Назначение:** Содержит общий банк вопросов для итогового тестирования. Из этой таблицы случайным образом выбирается 30 вопросов для формирования полного теста.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор вопроса, первичный ключ (PRIMARY KEY) |
| `question` | TEXT, NOT NULL | Текст вопроса |
| `option_a` | TEXT, NOT NULL | Вариант ответа A |
| `option_b` | TEXT, NOT NULL | Вариант ответа B |
| `option_c` | TEXT, NOT NULL | Вариант ответа C |
| `option_d` | TEXT, NOT NULL | Вариант ответа D |
| `correct_answer` | ENUM('A', 'B', 'C', 'D'), NOT NULL | Правильный вариант ответа |
| `topic_id` | INT, NULL | Идентификатор темы (может быть NULL, если вопрос не привязан к конкретной теме) |

**Особенности:**
- Всего в банке более 25 вопросов (покрывают все 4 темы)
- При генерации полного теста из банка случайным образом выбираются 30 вопросов
- Поле `topic_id` может быть NULL для общих вопросов, не привязанных к конкретной теме
- Порядок вопросов в тесте — случайный (ORDER BY RAND())
- Вопросы можно редактировать, добавлять и удалять через кабинет преподавателя

**Связи:**
- С таблицей `theory_topics` через внешний ключ `full_tests.topic_id` → `theory_topics.id` (при удалении темы поле topic_id становится NULL — ON DELETE SET NULL)

**Пример записи:**
| id | question | option_a | option_b | option_c | option_d | correct_answer | topic_id |
|----|-----------|----------|----------|----------|----------|---------------|----------|
| 25 | Какой тип памяти имеет наименьшую ёмкость? | HDD | ОЗУ | Кэш | Регистры | D | NULL |

## 6) Таблица «test_results» — результаты тестирования

**Назначение:** Содержит историю прохождения тестирования студентами. Сохраняет результаты как мини-тестов, так и полного теста. Данные доступны преподавателю для анализа успеваемости.

**Поля таблицы:**

| Поле | Тип данных | Описание |
|------|------------|----------|
| `id` | INT, AUTO_INCREMENT | Уникальный идентификатор результата, первичный ключ (PRIMARY KEY) |
| `user_id` | INT, NOT NULL | Идентификатор студента, прошедшего тест, внешний ключ → users.id |
| `score` | INT, NOT NULL | Количество правильных ответов |
| `total_questions` | INT, NOT NULL | Общее количество вопросов в тесте |
| `percentage` | DECIMAL(5,2), NOT NULL | Процент правильных ответов (например: 83.33) |
| `test_type` | ENUM('mini', 'full'), NOT NULL | Тип теста: «mini» — мини-тест по теме, «full» — полный тест |
| `topic_id` | INT, NULL | Идентификатор темы (только для мини-тестов), внешний ключ → theory_topics.id |
| `started_at` | DATETIME, DEFAULT CURRENT_TIMESTAMP | Дата и время начала теста |
| `completed_at` | DATETIME, DEFAULT CURRENT_TIMESTAMP | Дата и время завершения теста |

**Особенности:**
- Запись создаётся только после успешного завершения теста (нажатие кнопки «Завершить тест»)
- Для мини-тестов поле `topic_id` содержит ID темы, для полных тестов — может быть NULL
- Поле `percentage` рассчитывается как `(score / total_questions) * 100` и округляется до 2 знаков
- Студент может проходить тесты многократно; сохраняется история всех попыток
- Преподаватель видит результаты всех студентов с возможностью фильтрации по группам и сортировки

**Связи:**
- С таблицей `users` через внешний ключ `test_results.user_id` → `users.id` (при удалении пользователя удаляются все его результаты — ON DELETE CASCADE)
- С таблицей `theory_topics` через внешний ключ `test_results.topic_id` → `theory_topics.id` (при удалении темы поле topic_id становится NULL — ON DELETE SET NULL)

**Пример записи:**
| id | user_id | score | total_questions | percentage | test_type | topic_id | started_at | completed_at |
|----|---------|-------|----------------|------------|-----------|----------|------------|---------------|
| 10 | 5 | 25 | 30 | 83.33 | full | NULL | 2026-05-04 10:30:00 | 2026-05-04 10:45:00 |
| 11 | 5 | 3 | 4 | 75.00 | mini | 1 | 2026-05-04 11:00:00 | 2026-05-04 11:05:00 |

## Схема связей (ER-диаграмма в текстовом виде)

```
groups (1) ────── (∞) users (∞) ────── (∞) test_results
                             │
                             │
theory_topics (1) ── (∞) mini_tests
             │
             └── (∞) full_tests
             │
             └── (∞) test_results (только для mini-тестов, поле topic_id)
```

**Легенда:**
- (1) — одна запись
- (∞) — много записей
- ────── — связь между таблицами

## SQL-запросы для работы с таблицами

### Просмотр всех таблиц:
```sql
SHOW TABLES;
```

### Просмотр структуры таблицы:
```sql
DESCRIBE users;
DESCRIBE theory_topics;
DESCRIBE mini_tests;
DESCRIBE full_tests;
DESCRIBE test_results;
DESCRIBE groups;
```

### Пример выборки с JOIN (результаты с ФИО студентов и названиями групп):
```sql
SELECT 
    tr.id,
    u.last_name,
    u.first_name,
    g.name as group_name,
    tr.score,
    tr.total_questions,
    tr.percentage,
    tr.test_type,
    tr.completed_at
FROM test_results tr
JOIN users u ON tr.user_id = u.id
LEFT JOIN groups g ON u.group_id = g.id
ORDER BY tr.completed_at DESC;
```
