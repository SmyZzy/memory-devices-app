1. ОБЩИЕ СВЕДЕНИЯ
--------------------------------------------------------------------------------
Название:    Запоминающие устройства ЭВМ — компьютерное сопровождение дисциплины
Платформа:   Веб-приложение (доступно из любого браузера)
Технологии:  Node.js, Express.js, MySQL, HTML5, CSS3, JavaScript
Хеширование: BCrypt (bcryptjs)
Безопасность: express-session для управления сессиями, валидация пароля (мин. 8 символов)

2. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
--------------------------------------------------------------------------------

2.1. Форма входа (login.html)
- Поля: логин (username), пароль (password)
- Валидация пароля: минимум 8 символов на клиенте и на сервере
- Хеширование паролей: BCrypt с saltRounds = 10
- При успешном входе перенаправление на соответствующий кабинет (студент/преподаватель)
- При ошибке — отображение сообщения об ошибке
- Сессия хранится в express-session (cookie-based)

2.2. Главная страница (index.html)
- Название дисциплины и темы
- Краткое описание системы
- Навигация: Теория, Тестирование, Кабинет (если авторизован), Вход/Выйти
- Карточки с кратким описанием разделов (Теория, Мини-тесты, Полное тестирование)

2.3. Страница теории (theory.html, theory-detail.html)
- Список 4 тем курса
- Каждая тема содержит:
  - Название
  - Краткое содержание (HTML-формат)
  - Мини-тест после теории (4 вопроса на тему)
  - Ссылка на файл с полным текстом темы (файлы хранятся в public/files/)
- Навигация: список тем → детальная страница темы

2.4. Страница полного тестирования (test.html)
- 30 вопросов по всем темам в случайном порядке (ORDER BY RAND())
- Минимум 20 вопросов (сейчас: 30)
- Каждый вопрос — 4 варианта ответа (A, B, C, D)
- Возможность неза завершенного теста с предупреждением
- Результат: количество правильных ответов, процент, оценка
- Сохранение результата в БД (test_results)

2.5. Личный кабинет студента (student.html)
- Информация: ФИО, логин, группа, дата регистрации
- Редактирование ФИО
- Смена пароля (требуется текущий пароль, новый пароль мин. 8 символов)
- Таблица результатов тестирования (дата, тип теста, тема, результат, процент)

2.6. Личный кабинет преподавателя (teacher.html)
- Информация: ФИО, логин
- Редактирование ФИО
- Вкладка «Статистика»:
  - Таблица результатов всех студентов
  - Фильтр по группе
  - Сортировка: по дате, по баллам (проценту), по группе, по результату
  - Направление сортировки: по возрастанию / убыванию
- Вкладка «Аккаунты»:
  - Генерация логин/пароль для студентов по группе и количеству
  - Случайные уникальные логины + случайные пароли (hex, 8 символов)
  - Возможность копирования сгенерированных данных
  - Список всех студентов с возможностью удаления
- Вкладка «Редактирование теории»:
  - Изменение названия, содержания, пути к файлу каждой темы
- Вкладка «Редактирование тестов»:
  - Изменение вопросов полного теста (текст, варианты, правильный ответ)
  - Удаление вопросов
  - Добавление новых вопросов

3. СТРУКТУРА БАЗЫ ДАННЫХ (MySQL)
--------------------------------------------------------------------------------

3.1. Таблица groups
- id (INT, AUTO_INCREMENT, PK)
- name (VARCHAR(50), UNIQUE)
Описание: учебные группы студентов

3.2. Таблица users
- id (INT, AUTO_INCREMENT, PK)
- username (VARCHAR(100), UNIQUE)
- password (VARCHAR(255)) — хеш BCrypt
- role (ENUM: 'student', 'teacher')
- first_name (VARCHAR(100))
- last_name (VARCHAR(100))
- middle_name (VARCHAR(100))
- group_id (INT, FK → groups.id)
- created_at (DATETIME)
Описание: все пользователи системы (студенты и преподаватели)

3.3. Таблица theory_topics
- id (INT, AUTO_INCREMENT, PK)
- title (VARCHAR(255))
- short_content (TEXT) — краткое содержание (HTML)
- file_path (VARCHAR(255)) — путь к файлу с полной теорией
- order_num (INT) — порядок отображения
Описание: темы курса

3.4. Таблица mini_tests
- id (INT, AUTO_INCREMENT, PK)
- topic_id (INT, FK → theory_topics.id)
- question (TEXT)
- option_a, option_b, option_c, option_d (TEXT)
- correct_answer (ENUM: 'A', 'B', 'C', 'D')
Описание: вопросы мини-тестов (привязаны к конкретной теме)

3.5. Таблица full_tests
- id (INT, AUTO_INCREMENT, PK)
- question (TEXT)
- option_a, option_b, option_c, option_d (TEXT)
- correct_answer (ENUM: 'A', 'B', 'C', 'D')
- topic_id (INT, FK → theory_topics.id, NULL)
Описание: вопросы полного тестирования (по всей теории)

3.6. Таблица test_results
- id (INT, AUTO_INCREMENT, PK)
- user_id (INT, FK → users.id)
- score (INT) — количество правильных ответов
- total_questions (INT) — всего вопросов
- percentage (DECIMAL(5,2)) — процент правильных
- test_type (ENUM: 'mini', 'full')
- topic_id (INT, FK → theory_topics.id, NULL)
- started_at (DATETIME)
- completed_at (DATETIME)
Описание: результаты прохождения тестов

4.2. Описание серверных файлов:

server.js
- Создаёт Express-приложение
- Настраивает middleware: JSON parsing, session, static files
- Раздаёт HTML-файлы по соответствующим URL
- Подключает API-маршруты (routes/*)
- Запускает сервер на порту 3000

database/init.js
- Подключается к MySQL
- Создаёт базу данных memory_devices_db
- Создаёт все 6 таблиц с foreign keys
- Заполняет демо-данными:
  - Преподаватель: admin / teacher123
  - 5 студентов (ivanov1, petrov1, sidorov1, kuznetsov1, popov1) / student123
  - 4 темы с контентом
  - 16 вопросов мини-тестов (по 4 на тему)
  - 30 вопросов полного теста
  - 5 групп (ИС-101, ИС-102, ИС-201, ИС-202, ИС-301)
- Выполняется ОДИН раз при первом запуске

database/pool.js
- Создаёт connection pool к MySQL
- Экспортирует объект pool для использования в routes/*

routes/auth.js
- POST /api/auth/login — авторизация (проверка логина, BCrypt пароля)
- POST /api/auth/logout — выход из системы
- GET /api/auth/me — получение данных текущего пользователя

routes/theory.js
- GET /api/theory/topics — список всех тем
- GET /api/theory/:id — тема по ID
- GET /api/theory/:id/mini-test — вопросы мини-теста темы
- PUT /api/theory/:id — обновление темы

routes/test.js
- GET /api/test/full — все вопросы полного теста (случайный порядок)
- POST /api/test/full/submit — отправка полного теста, сохранение результата
- POST /api/test/mini/submit — отправка мини-теста, сохранение результата

routes/student.js
- GET /api/student/profile — данные студента
- PUT /api/student/profile — обновление ФИО
- POST /api/student/change-password — смена пароля
- GET /api/student/results — результаты тестирования студента

routes/teacher.js
- GET /api/teacher/profile — данные преподавателя
- PUT /api/teacher/profile — обновление ФИО
- GET /api/teacher/statistics — статистика с фильтрами и сортировкой
- GET /api/teacher/groups — список групп
- GET /api/teacher/students — список студентов
- POST /api/teacher/generate-accounts — генерация аккаунтов
- DELETE /api/teacher/account/:id — удаление студента
- GET/PUT /api/teacher/theory-topics/* — CRUD теории
- GET/POST/PUT/DELETE /api/teacher/full-tests/* — CRUD вопросов
- GET/POST/PUT/DELETE /api/teacher/mini-tests/* — CRUD мини-тестов

5. API ENDPOINTS
--------------------------------------------------------------------------------

Авторизация:
  POST /api/auth/login        → { username, password } → { success, role }
  POST /api/auth/logout       → { success }
  GET  /api/auth/me           → { user: { id, username, role, first_name, last_name } }

Теория:
  GET  /api/theory/topics                    → { topics: [{ id, title, order_num }] }
  GET  /api/theory/:id                       → { topic: { id, title, short_content, file_path } }
  GET  /api/theory/:id/mini-test             → { questions: [mini_test_questions] }
  PUT  /api/theory/:id                       → { success }

Тестирование:
  GET  /api/test/full                        → { questions: [full_test_questions] }
  POST /api/test/full/submit                 → { answers: { questionId: answer } } → { score, total, percentage }
  POST /api/test/mini/submit                 → { topicId, answers } → { score, total, percentage }

Студент:
  GET  /api/student/profile                  → { user: { ... } }
  PUT  /api/student/profile                  → { first_name, last_name, middle_name }
  POST /api/student/change-password          → { current_password, new_password }
  GET  /api/student/results                  → { results: [test_results] }

Преподаватель:
  GET  /api/teacher/profile                  → { user: { ... } }
  PUT  /api/teacher/profile                  → { first_name, last_name, middle_name }
  GET  /api/teacher/statistics               → ?group_id=&sort_by=&sort_order=
  GET  /api/teacher/groups                   → { groups: [{ id, name }] }
  GET  /api/teacher/students                 → { students: [{ id, username, ... }] }
  POST /api/teacher/generate-accounts        → { group_id, count, password_prefix } → { generated: [{ username, password }] }
  DELETE /api/teacher/account/:id            → { success }
  GET/PUT /api/teacher/theory-topics/*       → CRUD тем
  GET/POST/PUT/DELETE /api/teacher/full-tests/*  → CRUD вопросов полного теста
  GET/POST/PUT/DELETE /api/teacher/mini-tests/*  → CRUD вопросов мини-теста

9. ОСОБЕННОСТИ
--------------------------------------------------------------------------------

- Все файлы фронтенда — чистые .html (без серверных шаблонизаторов)
- Навбар генерируется динамически через navbar.js
- Данные передаются через fetch API (AJAX)
- Сессии хранятся в памяти сервера (можно заменить на Redis для production)
- Файлы теории хранятся в public/files/ и доступны по /files/имя_файла
- Вопросы полного теста перемешиваются через ORDER BY RAND()
- Мини-тесты привязаны к конкретной теме
- Все пароли хешируются через BCrypt
- Преподаватель может редактировать теорию и вопросы через админ-панель
- Генерация аккаунтов создаёт уникальные логины + случайные пароли
