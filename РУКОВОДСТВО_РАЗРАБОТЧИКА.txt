1. ТЕХНОЛОГИЧЕСКИЙ СТЕК
--------------------------------------------------------------------------------

Backend:
  - Node.js 14+ (серверная среда выполнения)
  - Express.js 5.x (веб-фреймворк, маршрутизация, middleware)
  - mysql2 (драйвер для подключения к MySQL)
  - bcryptjs (хеширование паролей, алгоритм BCrypt)
  - express-session (управление сессиями пользователей)
  - dotenv (загрузка переменных окружения из .env)

Database:
  - MySQL 8+ (реляционная СУБД)
  - Connection Pool (mysql2/promise — пул подключений)

Frontend:
  - HTML5 (8 страниц, чистый HTML без шаблонизаторов)
  - CSS3 (тёмная тема, CSS-переменные, адаптивная вёрстка)
  - Vanilla JavaScript (fetch API, динамический навбар)

Security:
  - BCrypt хеширование (saltRounds = 10)
  - Валидация пароля (минимум 8 символов на клиенте и сервере)
  - Session-based авторизация (express-session, cookie)
  - Защита SQL-инъекций (parameterized queries через mysql2)

3. ПОДКЛЮЧЕНИЕ К БАЗЕ ДАННЫХ (ПОШАГОВО)
--------------------------------------------------------------------------------

Шаг 1: Установить MySQL Server
  - Скачайте с https://dev.mysql.com/downloads/mysql/
  - Или используйте MySQL Workbench (содержит сервер)
  - Запомните пароль пользователя root

Шаг 2: Запустить MySQL-сервер
  - Windows: запустите службу «MySQL80» через services.msc
  - Или откройте MySQL Workbench — сервер запустится автоматически

Шаг 3: Настроить .env
  Откройте файл .env и укажите свои данные:

    PORT=3000
    SESSION_SECRET=любой_секретный_текст_для_сессий

    DB_HOST=localhost
    DB_USER=root
    DB_PASSWORD=ваш_пароль_от_mysql
    DB_NAME=memory_devices_db
    DB_PORT=3306

Шаг 4: Установить зависимости (один раз)
  Откройте терминал в папке memory-devices-app:
    npm install

Шаг 5: Инициализировать базу данных
    npm run db:init
  или
    node database/init.js

  Скрипт сделает:
    1. Подключится к MySQL под пользователем root
    2. Создаст базу данных memory_devices_db (если нет)
    3. Создаст 6 таблиц: groups, users, theory_topics, mini_tests, full_tests, test_results
    4. Заполнит демо-данными (только если таблицы пустые)
    5. Выведет сообщения в консоль

Шаг 6: Запустить сервер
    npm start
  или
    node server.js

  Сервер запустится на http://localhost:3000

--------------------------------------------------------------------------------

ТАБЛИЦА: groups (Учебные группы)
Назначение: Справочник учебных групп, к которым привязываются студенты.

  ┌──────────────┬──────────────┬──────────────────────────────────────────┐
  │ Поле         │ Тип          │ Описание                                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ id           │ INT, PK, AI  │ Уникальный идентификатор группы.         │
  │              │              │ Автоматически увеличивается при добавле- │
  │              │              │ нии новой группы.                        │
  │              │              │ Пример: 1, 2, 3                          │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ name         │ VARCHAR(50), │ Название группы. Уникальное значение.    │
  │              │ UNIQUE       │ Используется при регистрации студента    │
  │              │              │ и в статистике преподавателя.            │
  │              │              │ Пример: 'ИС-101', 'ИС-202'               │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  Примеры записей:
    id=1, name='ИС-101'
    id=2, name='ИС-102'
    id=3, name='ИС-201'

  │              │              │ темы. Отображается на странице деталей   │

  │              │              │ <li>, <strong> и т.д.                    │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ file_path    │ VARCHAR(255),│ Путь к файлу полной лекции (PDF, DOCX). │
  │              │ NULL         │ Относительный путь: '/files/lecture1.pdf'│
  │              │              │ Если NULL — файл не прикреплён.          │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ order_num    │ INT          │ Порядковый номер для сортировки тем.     │
  │              │              │ Темы отображаются в порядке возрастания. │
  │              │              │ Пример: 1, 2, 3, 4                       │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  Примеры записей:
    id=1, title='Тема 1. Оперативная память', order_num=1
    id=2, title='Тема 2. Кеш-память', order_num=2

ТАБЛИЦА: mini_tests (Вопросы мини-тестов)
Назначение: Вопросы для проверки знаний по конкретной теме (по 4 вопроса на тему).

  ┌──────────────┬──────────────┬──────────────────────────────────────────┐
  │ Поле         │ Тип          │ Описание                                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ id           │ INT, PK, AI  │ Уникальный ID вопроса.                   │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ topic_id     │ INT, FK      │ ID темы из theory_topics. Привязывает    │
  │              │              │ вопрос к конкретной теме. При удалении   │
  │              │              │ темы вопросы удаляются автоматически     │
  │              │              │ (ON DELETE CASCADE).                     │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ question     │ TEXT         │ Текст вопроса, который видит студент.    │
  │              │              │ Пример: 'Для чего предназначена ОЗУ?'    │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_a     │ TEXT         │ Текст варианта ответа A.                 │
  │              │              │ Пример: 'Для долговременного хранения'   │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_b     │ TEXT         │ Текст варианта ответа B.                 │
  │              │              │ Пример: 'Для работы ОС и приложений'     │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_c     │ TEXT         │ Текст варианта ответа C.                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_d     │ TEXT         │ Текст варианта ответа D.                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ correct_answer│ ENUM('A',  │ Буква правильного ответа. Принимаются    │
  │              │ 'B', 'C',   │ только значения: 'A', 'B', 'C' или 'D'.  │
  │              │ 'D')         │ Сравнивается с ответом студента при      │
  │              │              │ проверке мини-теста.                     │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  Пример записи:
    id=1, topic_id=1, question='Для чего предназначена ОЗУ?',
    option_a='Для долговременного хранения файлов',
    option_b='Для работы ОС и приложений',
    option_c='Для подключения к сети',
    option_d='Для вывода изображения',
    correct_answer='B'

ТАБЛИЦА: full_tests (Вопросы полного теста)
Назначение: Вопросы для итогового тестирования (30 вопросов, случайный порядок).

  ┌──────────────┬──────────────┬──────────────────────────────────────────┐
  │ Поле         │ Тип          │ Описание                                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ id           │ INT, PK, AI  │ Уникальный ID вопроса.                   │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ question     │ TEXT         │ Текст вопроса.                           │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_a     │ TEXT         │ Вариант ответа A.                        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_b     │ TEXT         │ Вариант ответа B.                        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_c     │ TEXT         │ Вариант ответа C.                        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ option_d     │ TEXT         │ Вариант ответа D.                        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ correct_answer│ ENUM('A',  │ Буква правильного ответа ('A'-'D').      │
  │              │ 'B', 'C',   │ Используется для подсчёта результатов.   │
  │              │ 'D')         │                                          │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ topic_id     │ INT, FK,     │ ID темы из theory_topics. Может быть     │
  │              │ NULL         │ NULL — тогда вопрос считается «общим»    │
  │              │              │ и не привязан к конкретной теме.         │
  │              │              │ При удалении темы значение ставится в    │
  │              │              │ NULL (ON DELETE SET NULL).               │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  Отличие от mini_tests:
    - full_tests.topic_id может быть NULL (вопрос из нескольких тем)
    - Вопросы из full_tests выдаются в случайном порядке (ORDER BY RAND())
    - full_tests не удаляются при удалении темы (ставится NULL)

ТАБЛИЦА: test_results (Результаты тестирования)
Назначение: Хранит результаты всех пройденных тестов (мини и полных).

  ┌──────────────┬──────────────┬──────────────────────────────────────────┐
  │ Поле         │ Тип          │ Описание                                 │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ id           │ INT, PK, AI  │ Уникальный ID записи о результате.       │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ user_id      │ INT, FK      │ ID пользователя из таблицы users.        │
  │              │              │ Показывает, КТО проходил тест.           │
  │              │              │ При удалении пользователя результаты     │
  │              │              │ удаляются (ON DELETE CASCADE).           │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ score        │ INT          │ Количество ПРАВИЛЬНЫХ ответов.           │
  │              │              │ Подсчитывается сервером при отправке     │
  │              │              │ теста. Например: 24 (из 30).             │
  │              │              │ Диапазон: 0 до total_questions.          │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ total_questions│INT         │ Общее количество вопросов в тесте.       │
  │              │              │ Для полного теста обычно: 30             │
  │              │              │ Для мини-теста: 4                        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ percentage   │ DECIMAL(5,2) │ Процент правильных ответов.              │
  │              │              │ Формула: (score / total_questions) * 100 │
  │              │              │ Формат: 80.00, 66.67, 100.00 и т.д.      │
  │              │              │ Максимум 5 цифр, 2 после запятой.        │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ test_type    │ ENUM('mini', │ Тип пройденного теста:                   │
  │              │ 'full')      │ 'mini' — мини-тест по одной теме         │
  │              │              │ 'full' — полный тест (30 вопросов)       │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ topic_id     │ INT, FK,     │ ID темы из theory_topics. Заполняется    │
  │              │ NULL         │ ТОЛЬКО для мини-тестов. Для полного      │
  │              │              │ теста — NULL (тест охватывает все темы). │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ started_at   │ DATETIME     │ Дата и время НАЧАЛА прохождения теста.   │
  │              │              │ Устанавливается автоматически.           │
  │              │              │ Пример: '2025-03-15 10:30:00'            │
  ├──────────────┼──────────────┼──────────────────────────────────────────┤
  │ completed_at │ DATETIME     │ Дата и время ЗАВЕРШЕНИЯ теста.           │
  │              │              │ Устанавливается при отправке ответов.    │
  │              │              │ Пример: '2025-03-15 10:45:00'            │
  └──────────────┴──────────────┴──────────────────────────────────────────┘

  Примеры записей:
    id=1, user_id=2, score=24, total_questions=30, percentage=80.00,
         test_type='full', topic_id=NULL, started_at='2025-03-15 10:30:00',
         completed_at='2025-03-15 10:45:00'
    id=2, user_id=2, score=3, total_questions=4, percentage=75.00,
         test_type='mini', topic_id=1, started_at='2025-03-15 11:00:00',
         completed_at='2025-03-15 11:05:00'

  Как используется:
    - Студент видит свои результаты в кабинете (GET /api/student/results)
    - Преподаватель видит статистику всех студентов (GET /api/teacher/statistics)
    - По percentage определяется оценка (если преподаватель задаст пороги)

5. КАК ЭКСПОРТИРОВАТЬ / ИМПОРТИРОВАТЬ БАЗУ ДАННЫХ
--------------------------------------------------------------------------------

5.1. Экспорт (сохранение данных с текущего компьютера)

Через командную строку (mysqldump):
  mysqldump -u root -p memory_devices_db > backup_memory_devices.sql
  (введите пароль MySQL)

Через MySQL Workbench:
  1. Откройте MySQL Workbench, подключитесь к серверу
  2. В верхнем меню: Server → Data Export
  3. Выберите базу данных: memory_devices_db
  4. Выберите «Export to Self-Contained File»
  5. Укажите путь для сохранения файла .sql
  6. Нажмите «Start Export»

Через HeidiSQL / phpMyAdmin:
  - Выберите базу → Экспорт → формат SQL → Скачать

5.2. Импорт (восстановление данных на другом компьютере)

Сначала убедитесь что MySQL установлен и запущен на новом компьютере.

Через командную строку:
  mysql -u root -p < backup_memory_devices.sql
  (введите пароль MySQL)

Через MySQL Workbench:
  1. Откройте MySQL Workbench, подключитесь к серверу
  2. В верхнем меню: Server → Data Import
  3. Выберите «Import from Self-Contained File»
  4. Укажите путь к файлу backup_memory_devices.sql
  5. Выберите «Default Target Schema» → memory_devices_db
  6. Нажмите «Start Import»

Через HeidiSQL:
  1. Подключитесь к серверу
  2. Файл → Загрузить SQL-файл → выберите backup_memory_devices.sql
  3. Выполнить

5.3. Полный перенос на другой компьютер:

ШАГ 1. На старом компьютере:
  а) Экспортируйте БД (см. 5.1) → получите backup_memory_devices.sql
  б) Скопируйте ВСЮ папку memory-devices-app на флешку/диск
     (ВКЛЮЧАЯ node_modules, .env, все файлы)

ШАГ 2. На новом компьютере:
  а) Установите Node.js (https://nodejs.org)
  б) Установите MySQL Server
  в) Вставьте флешку, скопируйте папку memory-devices-app куда угодно
  г) Импортируйте БД (см. 5.2)
  д) Откройте .env и проверьте пароль MySQL (DB_PASSWORD)
  е) Откройте терминал в папке memory-devices-app:
        npm install
  ж) Запустите сервер:
        npm start
  з) Откройте браузер: http://localhost:3000

ВАЖНО: Если node_modules не скопированы (рекомендуется их не копировать,
а установить заново) — просто выполните npm install на новом компьютере.
Файл package.json содержит все зависимости.

8. API ENDPOINTS (ПОЛНЫЙ СПИСОК)
--------------------------------------------------------------------------------

Авторизация (без авторизации):
  POST /api/auth/login         → { username, password }
                                  → 200: { success: true, role: 'student'|'teacher' }
                                  → 400: { error: '...' }
                                  → 401: { error: 'Неверный логин или пароль' }

  POST /api/auth/register      → { username, password, first_name, last_name,
                                   middle_name?, group_id? }
                                  → 200: { success: true }
                                  → 400: { error: '...' }
                                  → 409: { error: 'Такой логин уже занят' }

  POST /api/auth/logout        → 200: { success: true }

  GET  /api/auth/me            → 200: { user: { id, username, role, ... } }
                                  → 401: { error: 'Не авторизован' }

  GET  /api/auth/groups        → 200: { groups: [{ id, name }] }

Теория (без авторизации):
  GET  /api/theory/topics      → 200: { topics: [{ id, title, order_num }] }
  GET  /api/theory/:id         → 200: { topic: { id, title, short_content, file_path } }
  GET  /api/theory/:id/mini-test → 200: { questions: [...] }

Тестирование:
  GET  /api/test/full          → 200: { questions: [...] } (ORDER BY RAND())
  POST /api/test/full/submit   → { answers: { questionId: 'A'|'B'|'C'|'D' } }
                                  → 200: { score, total, percentage }
                                  → 401: если не авторизован
  POST /api/test/mini/submit   → { topicId, answers }
                                  → 200: { score, total, percentage }
                                  → 401: если не авторизован

Студент (требуется авторизация, роль student):
  GET  /api/student/profile    → 200: { user: { id, username, first_name, last_name,
                                   middle_name, group_name, created_at } }
  PUT  /api/student/profile    → { first_name, last_name, middle_name }
  POST /api/student/change-password → { current_password, new_password }
  GET  /api/student/results    → 200: { results: [...] }

Преподаватель (требуется авторизация, роль teacher):
  GET  /api/teacher/profile    → данные преподавателя
  PUT  /api/teacher/profile    → обновить ФИО
  GET  /api/teacher/statistics → ?group_id=&sort_by=&sort_order=
  GET  /api/teacher/groups     → список групп
  GET  /api/teacher/students   → список студентов
  POST /api/teacher/generate-accounts → { group_id, count, password_prefix }
  DELETE /api/teacher/account/:id
  GET/PUT /api/teacher/theory-topics/*
  GET/POST/PUT/DELETE /api/teacher/full-tests/*
  GET/POST/PUT/DELETE /api/teacher/mini-tests/*

12. СТРУКТУРА СЕССИИ (express-session)
--------------------------------------------------------------------------------

При успешном входе сервер сохраняет в сессию:
  req.session.user = {
    id: 6,
    username: 'ivanov1',
    role: 'student',
    first_name: 'Иван',
    last_name: 'Иванов',
    middle_name: 'Иванович',
    group_id: 1
  }

Сессия хранится в памяти сервера (MemoryStore).
Для production рекомендуется заменить на Redis или connect-mysql.
Cookie сессии: maxAge = 24 часа.
